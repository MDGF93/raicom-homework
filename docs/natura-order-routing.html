The job

Natura Wellness sells 3 supplements and 1 bundle. It ships across the US from 4 warehouses. The router reads today's order events and picks one destination for each order. The destination is a warehouse, or PARTNER, the international partner warehouse.

Two things make the job harder than a table lookup. First, each routed order reserves its stock, so an early order can change where a later order goes. Second, the data is messy. One ZIP is a number, one SKU is lowercase, two orders use a bundle SKU that no warehouse stocks, and one edit adds an item 18 minutes after the order.

    The router also checks the input before it routes. Today's files pass every check. Each of these stops the run with an error that names the order, the warehouse, the bundle or the flag:

    • an event with no order number, or a time that is not a date
    • an unknown event type, such as order_cancelled
    • an order with no ship-to address or no country
    • a line with no SKU, or a quantity that is not a positive whole number
    • an order with no items
    • an edit for an order that was never created
    • a second order_created with different content
    • a warehouse code that is not in the priority list, or that appears twice
    • a warehouse with no inventory, or an inventory row without numbers
    • a table in zones.json whose key is not a warehouse code, such as "WH-nj"
    • a bundle that contains another bundle
    • a code in --off that is not a warehouse, an unknown flag, or --off with no value

    The router skips an exact copy of an event and adds a note. An edit that comes before its order_created in the file still merges. An edit more than 30 minutes after the order also merges, and its note warns about it. The router also trims and uppercases the country, pads a ZIP string of 1 to 4 digits such as "2134", and reads a zone that is not a number as no zone.

    Question 2: WH-GA until Monday

    Decision

    Ship option 3: route away from WH-GA only when another warehouse is within one zone of it.

    • WH-GA picks about 2 business days late. For 70% of its orders, the next warehouse adds about 2 days of transit. Those customers gain no time, and each parcel costs $2.35 more.
    • For the other 30%, the next warehouse adds about half a day. Those customers get their order about 1.5 days sooner, for $0.40 more.
    • Options 1 and 4 fail with today's network.
    • Option 4 sends orders to a warehouse with water damage.
    Conditions
    • Set WH-NV to disabled in the router first. IT has not changed it yet.
    • Make the rule end on Monday without a new deploy.
    • Priya's 30% probably counts WH-NV as an alternative. The real share is probably lower.

    Daily effect from Priya's numbers: about 420 WH-GA orders a day, so 294 orders at 70% and 126 orders at 30%. The chart assumes that 2 business days of picking delay equal about 2 days in transit.
