### Claude

Every variable, constant and function parameter in `src` now has an explicit type, for example `const prefix: string = zip.slice(0, 3);`. All 13 tests pass and `npm run route` prints the same routes as before. I did not type-check, so the annotations are untested. `tsx` strips types without checking them, and TypeScript is not installed in the project.

- **Real types instead of `any`:** `router.ts` now defines `OrderEvent`, `Warehouse`, `Bundle`, `InventoryItem`, `RouteOptions` and a few internal types. The old `any` fields in the test helpers use these types.
- **`loadData`:** it now reads each JSON file with a type, for example `read<OrderEvent[]>('orders.json')`.
- **Behavior-preserving rewrites:** I split the ZIP handling into `rawZip: unknown` and `zip: string`. The edit loop now uses an early `continue`. The `_note` filter checks `value !== null && typeof value === 'object'`.
- **Not annotated:** TypeScript does not allow a type on a `for...of` variable, such as `for (const event of ...)`. Those variables stay inferred. Test callbacks like `test('...', () => {...})` have no parameters and no return annotation.
